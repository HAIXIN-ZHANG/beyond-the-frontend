## 1. 读者的问题与本章目标

沿用 G01 的虚构课程网站，把镜头收回浏览器。设置两次观察：打开课程搜索页，标题迟迟没出现；另一次标题和搜索框已经出现，点搜索却没有及时反馈。两次都可以被用户称为“慢”，但需要调查的环节不同。

本章应使做过页面或接口的读者能够：

1. 解释 HTML、DOM、样式计算、布局和屏幕图像之间的关系，不把收到文件等同于功能可用。
2. 沿着“资源何时可用 → 谁执行代码 → 何时呈现更新”追踪一次加载与一次搜索。
3. 分开提出资源等待、主线程繁忙、行为未就绪/出错这几类假设，并知道需要什么证据；不凭截图或一个请求耗时直接判根因。
4. 看懂后续布局、组件与渲染策略讨论所需的最小模型，无须背浏览器内部流水线或事件循环面试题。

**编写判断：** 标题虽然讲“出现之前”，内容必须延伸到出现之后的一次交互，否则回答不了本章第二个问题。正文开头明确这个延伸。

## 3. 调研与关键主张

以下均于 **2026-11-15** 打开正文并阅读所列小节；没有通读整份标准或引用搜索摘要。HTML Living Standard 页面标示更新为 2026-11-14，属于滚动标准，不宣称所有当前浏览器已逐项实现。官方开发者文档用于说明常见实现及观察方法，不能代替跨浏览器实验。正文只选择与解释直接有关的少量引用；完整对照留在此处。

| S3：阻塞渲染与阻塞解析是不同的依赖 | [web.dev：Understand the critical path，Render-blocking resources / Parser-blocking resources](https://web.dev/learn/performance/understanding-the-critical-path#render-blocking-resources) | 常见浏览器行为：本例只用 head 中适用于当前媒体、启用的普通 stylesheet 说明首屏等待；等 CSS 时 HTML 可以继续解析。不要写“所有 CSS 在所有位置都阻止整个页面”，或“parser 停了所以浏览器停止一切取回”；资源扫描可先发现后续资源。 |

## 5. 原创案例、图示与实现窗口

### 案例 E1：同一个课程搜索页，三种不同的等待

**教学假设：** 普通桌面浏览器，前台可见标签页；初始 HTML 已包含标题、输入框、静态课程卡片；head 有适用的外部 CSS；一个外部 JS 为 `type="button"` 的搜索按钮安装处理函数。按钮初始 disabled，安装成功再启用；输入框保留原生输入行为。本章不实现后端、权限、缓存或搜索排序算法。

| 路径 | 仅改变的条件 | 要解释的差异 | 不允许推出的结论 |
| --- | --- | --- | --- |
| E1-A：资源尚未可用 | 人工延迟 head stylesheet；与正常加载对照 | HTML 解析、资源等待和可见结果不是一个时间点；具体首屏由条件决定。 | 看到空白就证明 CSS 慢；或所有图片都阻塞首屏。 |
| E1-B：增强行为未就绪/失败 | 延迟或拒绝搜索脚本，保持 CSS/HTML 正常 | 页面可以先有内容；本例按钮仍 disabled，错误需查 Network/Console。等待多久不是正确的状态判断。 | 所有原生交互失效；DOMContentLoaded 或外观足以证明监听器存在。 |
| E1-C：行为已就绪但处理被延迟 | 已成功安装监听器并启用按钮，用户按示例触发一次长同步计算，再尝试点击搜索 | 监听器存在仍可能等待执行；已呈现的内容可保留。 | 点击永远丢失、所有输入原生行为都完全停止、整台浏览器被阻塞。 |

E1-C 的长计算是刻意注入故障，不是现实课程数据规模的 benchmark；时长不能用固定循环次数跨设备保证。若正文需要显示“约几毫秒”，必须有后续实际环境与测量证据。

### 案例 E2：改颜色与改可用宽度

同一课程卡片，一次仅改文字颜色，另一次缩小容器可用宽度让长标题换行。前者解释无需重新求几何的可能路径，后者解释本卡片高度与后续卡片位置可能受影响。用 **可能受影响的范围**，不写每次全页重排/重绘。不要使用图片加载、字体替换和动画同时变化的示例，以免引入多个变量。

### 案例 E3：“正在搜索”为什么没来得及显示？

候选概念片段只表达：`设置提示 → 长同步筛选 → 写入结果` 在同一处理过程中发生，中间的提示不保证成为可见一帧。对照是等待真实异步请求的流程；请求等待期间主线程可能处理别的工作，但恢复后若又长计算，仍会卡。

不预写可复制运行代码，不把 `await Promise.resolve()` 或 `setTimeout(..., 0)` 当已经证明的修复。正文可用伪代码加时间线讲机制；若主审要求可运行窗口，先按 V3 验证，再把代码和证据纳入 F01M 的明确文件范围。

**类比取舍：** 不强制使用“浏览器是餐厅/工厂”。如需帮助理解主线程，可以短暂借用“同一张工作台一次处理一项眼前工作”，马上说明浏览器还有其他执行上下文与后台工作，不能把真实线程架构当成一家店。

**思考题草案：** “搜索框显示了，Network 里脚本也返回了 200，为什么仍不能断言搜索已可用？”解析应分别指出执行/安装可能未完成、运行时可能报错、主线程可能仍繁忙；还需查看按钮就绪条件和实际行为。200 只说明该次资源响应状态，不能替代产品验收。

# 标题长了半行，按钮去哪儿了？

设计稿里的课叫“摄影”。两字配一张山景，下面留着足够的空白，看着挺想报名。老师发来的全名是“带着旧手机去海边：阴天也能拍的周末摄影入门”，没有配图。你把这门课放回同一张卡片，才发现原来那份从容，有一大半是“摄影”这两个字替你挣来的。

假设这还是我们的课程列表。每张卡要回答三件事：上什么课，什么时候上，想继续了解该往哪儿走。图片有时能帮人选课，比如认出要学的构图；这位老师恰好没有图，读者仍该能靠文字选。先把山景拿走，看三件事还在不在，比替他临时找一张海鸥照片省事。

## 宽度花到哪里去了

假设窄屏上这张卡分到了 320 个 CSS 像素，两边各留 16 个像素，里面还剩 288。横排一张宽 96 的图，再留 16 的间距，留给文字和入口的就只有 176。你给卡片写上“宽度百分之百”，消失的那一百多像素也不会回来。盒子里的内容、内边距和边框各自占多少，要连同用的是哪种盒模型一起看。

在宽屏上，把多张卡放进网格往往很方便。每一列有自己的轨道，课程标题可以在列里换行。卡片内部若用 Flex 排图和文字，能不能缩小还受子项的最小尺寸约束。一串很长的课程代码，中间连一个可断的位置都没有，很可能把文字列撑出卡片。允许文字区收窄，例如给那个 flex 子项设 `min-width: 0`，是给盒子让路；让长代码有可接受的断行位置，是给内容让路。只做前一件，盒子缩进来了，字还可能伸在外头。

可以依次放进三张卡。第一张题目很长，但文字本身能换行；第二张塞进一串连着的课程代码；第三张干脆没有图。如果三张都固定为两行的总高度，第一张的讲课时间很容易被挤掉，第二张让你看见断行的限制，第三张则可能留下一个空空的相框。这些问题分开出现，比较容易知道刚改的那行样式究竟帮了谁。

## 少放一列以后

空间缩到图、字、入口要争位置时，可以把图放在上面，让标题按内容长高，时间和“查看课程”接在后面。也可以在这一级列表省去装饰图，让人先比较课程和场次。哪种好，要看图片有没有帮人分辨课程。若两门课的区别就在两张不同的画作上，删图之前，倒该先想想还有什么办法把这点区别交给读者。

有些设计喜欢把入口钉在卡片底部，让一排卡的按钮对齐。这很好看，前提是长标题也有地方安放。允许整排随内容增高，代价是短卡多些空白。把标题截成一行则节省了高度，可两门都从“周末摄影入门”开头的课，也许要读到最后三个字才能分开。亲手找一次“进阶班”，你很快就会知道省下的是谁的空间。

用键盘沿列表往下走，也值得看一遍。屏幕上第一张卡的标题、时间和入口挨在一起，文档里的顺序最好也让人能这样读下去。仅用视觉排序把第三张挪到最前，焦点还照原顺序走，读者的眼睛就得跟按钮玩捉迷藏。窄屏换行、放大文字、拿掉图片以后，读者仍该能看出焦点落在哪个入口上。卡片移入时轻轻抬起，本来只是装饰，即使关掉动效，选中状态和入口照样应该清楚。

把那门真的很长的摄影课放在第一张，再试一次。要是课程名读得完，周六的时间还在，“查看课程”也找得到，这张卡就已经比设计稿多回答了一个问题。接下来倒可以看看那个按钮。它在两页上长得一模一样，点它之前，学员知道自己会去哪里吗？

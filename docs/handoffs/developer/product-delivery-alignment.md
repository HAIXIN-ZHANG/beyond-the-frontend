## A. Local return and bookmarks — proposed bounded contract

### Minimal alternatives and decision

| Option | Cost / reliability | Recommendation |
| --- | --- | --- |
| Explicit “save this section” and return link, no automatic tracking | Smallest state surface; does not restore a reader who never saved. | Useful first bookmark slice, alongside an independently scoped resume slice. |
| Automatic last visible heading plus explicit Continue; manual bookmarks | One small client observer and a defensive store; avoids pixel/paragraph promises. | Recommended near-term target, after recovery/focus states are designed. Capture is automatic; restoration is deliberate. |
| Scroll pixels, paragraph ordinal or exact text selection as first target | Layout/font/device changes and edits invalidate positional assumptions; selection adds browser/IME complexity. | Defer. Do not call paragraph N or a DOM index a stable anchor. |

**Proposed types, not implemented schema:** `ReadingLocationV1 = { chapterId: string; locale: 'en' | 'zh'; sourceHash: string; target: { kind: 'chapter' } | { kind: 'heading'; headingId: string }; updatedAt: string }`. Use separate versioned envelopes for resume `{version: 1, location: ReadingLocationV1 | null}` and bookmarks `{version: 1, items: ReadingLocationV1[]}`. Build-time approved metadata resolves IDs to current routes/titles; stored data never supplies an arbitrary navigation URL, HTML, manuscript path, credential or executable expression. Store current public source revision to diagnose changes; titles are display data from current approved metadata. Reserve a fixed namespace for this guide, not a general multi-guide registry; a future guide identity/migration is Goal4 work.

Proposed client storage keys `vctw.reading.resume.v1` and `vctw.reading.bookmarks.v1` are independent of `btf.theme`. Treat serialized JSON as untrusted: validate object/version, locale, strings/lengths, SHA shape, timestamps, discriminated target, approved chapter/heading resolution and bounded list size; TypeScript alone is not runtime validation. Proposed caps are 50 bookmarks and bounded input bytes/strings, to be confirmed in implementation scope rather than presented as measured limits. Deduplicate by locale/chapter/target. Never render stored text as HTML.

Browser-owned/device-only data may be unavailable, cleared or lost; no cloud sync, backup, completion score or durable guarantee is implied. Read after hydration with an initially neutral server-rendered state. Catch access, parse and write/quota failures separately. Writes failing after an in-memory change must say “this visit only / not saved on this device”; do not announce persistence success before a successful write. Offer a deliberate clear/reset action, not repeated automatic destructive cleanup. Unknown newer versions must remain untouched until the reader explicitly resets or a reviewed migration exists.

### Resolution, restoration and state priority

1. **Navigation intent wins:** an incoming fragment, search-result link or explicit in-page link is the requested destination. Resume must not rewrite the URL, steal focus or scroll on mount. Browser back/forward restoration is preserved. An unknown shared fragment gets a missing-location explanation and an explicit chapter/outline action; it does not silently redirect to the locally saved place.
2. **Offer Continue:** on a neutral entry/index/chapter view, present a truthful saved-place label only after resolution. Activating it navigates with an ordinary generated chapter/heading link. An explicit bookmark may intentionally replace the current fragment after activation; it never does so merely on load. Current navigation keeps native destination focus semantics; no delayed focus return to an old toolbar.
3. **Observe only current reading:** after the reader is active, a bounded observer may track the last readable heading. Use a small, stable visible-heading rule and debounce writes; pause when the document is hidden or programmatic restoration is settling. Do not save the landing H1 during hydration before the saved state has been read. No per-pixel storage writes, reading-time analytics or completion claim.
4. **Resolve by identity/version, not a saved absolute URL:** same source hash plus existing target is valid. A changed hash is a changed-source state even if the same generated ID still exists: duplicate-heading suffixes can now refer to different material. Without a reviewed identity/alias mapping, offer chapter recovery and a labelled candidate section/outline for explicit reader choice, not automatic exact restoration. If the chapter is removed, offer the available-language index; never manufacture a counterpart. Save a new revision only after the reader chooses/reads it.
5. **Small concurrency contract:** last resume write wins. Bookmark-list mutations re-read/validate before saving and refresh on same-origin storage events; concurrent edits can still race because localStorage does not provide a transactional compare-and-swap. The initial proposal is explicit last-write-wins for simultaneous bookmark-list mutations, with no merge guarantee. Automatic resume capture must never rewrite the bookmark list. If lossless concurrent bookmark editing is required, review per-bookmark storage/tombstones or a transactional store in a separate design; do not silently add it.

| State | Reader-visible behavior / recovery | Future acceptance scenario |
| --- | --- | --- |
| No record / cleared data | Normal reading; bookmark action available, no false Continue target. | Empty store and cleared store leave all canonical links functional. |
| Same-version valid location | Label chapter/section; explicit Continue; saved bookmark toggle has a truthful accessible state. | Reload and cross-chapter return work in root/Pages, without jumping before activation. |
| Denied read/write or quota failure | Normal reading and in-memory actions; concise device-saving failure status, optional retry. | Throwing storage getter and failing write do not break hydration, search or navigation. |
| Malformed / oversized / unsupported version | Explain unavailable saved data; do not execute/use arbitrary URL or automatically overwrite future-version data; offer explicit reset. | Invalid JSON/types and future version are safe; reset is keyboard accessible and scoped to reading keys. |
| Changed hash / missing heading / changed duplicate | State that the location may have changed; chapter/outline or reviewed alias candidate requires deliberate action. | Rename, duplicate reorder and deleted heading never silently land on unrelated text. |
| Removed chapter / unavailable language | Label unavailable location; offer current index and retain useful context for removal/reset. | Deleted chapter and absent English body produce no fabricated article route. |
| Multiple tabs / delete / reset | Refresh displayed list on storage events; defined last-write-wins; reset does not alter appearance. | Two-tab writes, deletion, malformed external update and clear-all settle without an update loop. |
